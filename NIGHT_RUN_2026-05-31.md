## 1. Security fix — DONE + LIVE + VERIFIED

**Root cause (verified by reading code, not inferring):** `core/approval.py`
imported `app.policy.client_tool_policy` from agent-runtime — a module removed
2026-05-25 (confirmed: it exists nowhere; a test asserts `ModuleNotFoundError`).
So `_POLICY_OK` was False and the gate fell into a fallback that set every
decision to `approve` — no hard-DENY for anyone, and any conversation pinned to
`auto` (via the toast's "always for this conv") ran **every** client tool
(incl. `run_command`) silently. The running process was even older — the
*original* blanket-approve code.

**Two-part fix:**
1. **Fail-closed backstop** (`core/approval.py`): when the policy module can't
   load, force an approval toast even at `auto` (never silently run). Scoped so
   it only flips the silent case — `confirm`/`strict` and the `system:sandbox`
   short-circuit are untouched.
2. **Re-homed policy matrix** (`core/policy.py`, NEW) — restores a real matrix
   IN sub-agents (where the 2026-05-25 decision said it should live), grounded
   in the existing `CLIENT_TOOLS` set + `safety.validate_command`/`is_path_safe`:

   | Tools | Decision |
   |---|---|
   | read_file, search_files, grep, host_file_read | **ALLOW** (secret path → APPROVE) |
   | write_file, edit_file, host_file_write | **APPROVE** (protected path → DENY) |
   | run_command/cmd/powershell/docker/git | **APPROVE** (dangerous pattern → DENY) |
   | other CLIENT_TOOLS (no rule) | **APPROVE** |
   | non-client (cloud/memory/orchestration) | **ALLOW** |

   `core/approval.py` now imports `from .policy import classify, Decision,
   CLIENT_TOOLS` (dropped the dead agent-runtime sys.path probe). If the local
   module ever fails to import, the fail-closed backstop still applies.

**Tests:** `services/sub-agents/tests/test_approval.py` (NEW — this is the
canonical test the 2026-05-25 removal-note pointed to, which never existed).
15/15 pass: matrix decisions, gate integration (dangerous→deny, read+auto
