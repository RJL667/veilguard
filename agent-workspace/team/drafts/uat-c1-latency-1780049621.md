# Haiku vs Sonnet Latency Analysis

## Latency Deltas
- **Time-to-first-token (TTFT):** Haiku ~200–400 ms vs Sonnet ~600–1200 ms [unverified: research bridge offline]. Haiku is roughly 2–3× faster to first token.
- **End-to-end response:** Haiku completes short responses in ~1–2 s; Sonnet ~3–6 s for equivalent output length [unverified].

## User-Facing Impact
Sub-500 ms TTFT is perceived as near-instant; Haiku consistently hits this threshold. Sonnet's higher latency is noticeable on interactive queries but acceptable for batch or complex reasoning tasks.

## Recommendation
Route Director to **Haiku** for latency-sensitive, high-frequency decisions (triage, classification, quick lookups). Reserve Sonnet for tasks requiring deeper reasoning where response quality outweighs speed. This split routing minimises perceived lag while preserving quality where it matters.
