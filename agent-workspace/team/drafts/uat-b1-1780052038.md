# Internal Memo: Server-Side Prompt Caching

## TLDR

Server-side prompt caching reduces inference latency and token costs by reusing computed KV-states for repeated prompt prefixes. The gains are real but introduce cache invalidation complexity and stale-context risk that must be managed explicitly.

## Recommendation

Adopt caching for stable, high-frequency prompt prefixes (system prompts, static context). Disable or TTL-bound caching for any context that encodes session state, user-specific data, or rapidly-changing information. Implement explicit invalidation hooks on prompt template changes. The latency and cost savings justify adoption; the risk is manageable with disciplined cache-key design and short TTLs on dynamic segments.
